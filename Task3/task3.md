Необходимо прдумать более детально способ получения актуальных тарифов у страховых компаний. Как минимум, вместе с тарифом получать строк окончания его действия. Иначе из-за недоступности API страховых компаний, и текущего сопособа взаимодейтсвия с ними, возможно продать уже не существующий продукт или продать продукт по заниженной цене. 

Далее исходим из предположения, что мы управляем только собственным рещением.

# Проблемы при росте нагрузки

# Проблема 1

Сервис ins-comp-settlement раз в сутки осуществляет запрос в core-app по REST API для получения всех оформленных за день страховок.

Со временем, количество данных об оформленных за день страховках будет увеличиваться, на сеть и севис сore-app будет создаваться бОльшая нагрузка.

# Проблема 2

Сервис ins-product-aggregator в момент обращения к нему синхронно запрашивает информацию из всех страховых компаний.

При увеличении кол-ва партнеров, вероятность ошибки или медленного ответа хотя бы у одного из них будет возрастать.

# Проблема 3

Сервис core-app осуществляет запрос к ins-product-aggregator раз в 15 минут, а ins-comp-settlement — раз в сутки (ночью), при формировании реестра оформленных страховок.

При увеличении кол-ва партнеров, объем передаваемой информации будет возрастать. К тому же мы будет запрашивать одну и туже информацию многократно (так как тарифы на страховые продукты меняются реже 1 дня)
